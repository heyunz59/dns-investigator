## 证据归属

ToolBackend 保存按 A 调用 ID 索引的证据集合，所有测量经同一同步分配/保存入口获得唯一 E 编号。入口无 await，不依赖完成顺序；实际 DNS 返回的 evidence_id 必须属于当前调用，否则拒绝。简单工具保存自己的测量；复合只读取自己的子证据集合，不使用全局长度变化、切片或最后一条记录推断归属。

保存证据时快照复制，fixture 数据也独立复制，防止运行时编号或返回元数据回写到历史测量/fixture。证据快照不再在 JSONL 写出后更新耗时；调用耗时与测量耗时分别记录。finally 为成功、取消、超时统一记录所属 evidence_ids；错误返回的 partial_evidence 只取当前调用。

并发仍保留。asyncio.Event 控制 DNS→HTTP、HTTP→DNS、两个 HTTP、复合与 HTTP、取消/超时交错，不使用短 sleep 决定完成顺序。另用脚本模型同时发出 DNS/HTTP 调用，核对框架 provider_call_id → A → E、可见工具返回、最终引用、JSON 和 JSONL。脚本模型仅是离线基础设施测试。

## DNS 分类依据与边界

协议依据：[RFC 2308 §2.1](https://www.rfc-editor.org/rfc/rfc2308.html#section-2.1)、[§2.2](https://www.rfc-editor.org/rfc/rfc2308.html#section-2.2)、[§2.2.1](https://www.rfc-editor.org/rfc/rfc2308.html#section-2.2.1)，以及 [RFC 1034](https://www.rfc-editor.org/rfc/rfc1034.html) 的别名处理背景。RCODE、相关 Answer、Authority 的 SOA/NS 和相关名称共同分类；AA 可能只覆盖别名所在区，不要求带 CNAME 的转介必须 AA=0。

从原始 qname 按名称关系遍历 CNAME，支持未排序链，忽略无关 Answer；记录 canonical_name。仅链末端相应类型的记录满足 A/AAAA 查询。TC 优先产生 TRUNCATED，不生成最终负回答；循环或冲突链保留 INDETERMINATE。NXDOMAIN 优先于 Authority 中的 NS；经过 CNAME 时，其否定范围是链末端，而非别名本身。

NOERROR 下，相关 SOA 支持 NODATA，SOA 与 NS 并存仍可为负回答；只有相关 NS 时为 REFERRAL。不相关的 SOA/NS 不能证明目标不存在。无 CNAME、无相关 Answer 且无 NS 的空响应保留 RFC 2308 type 3 NODATA。仅含 CNAME 而缺少可确认末端结果时，按照 §2.2.1 的实现缺陷风险保守标 ALIAS_INCOMPLETE，建议另查链末端，不强行确认 NODATA/NXDOMAIN。

Diagnosis Engine 只根据明确 result_kind=NODATA 生成 NODATA_OBSERVED，不重新用 NOERROR+空 records 推断。负回答 Finding 指明 negative_name。转介、未完成别名、截断、无法确定结果，以及旧格式无分类的空 NOERROR，不与完整回答直接生成递归/权威故障差异；比较返回 COMPARISON_INCONCLUSIVE。旧日志保持原样，不追溯改写旧实验结果。

测试包含所需八类报文，另外覆盖 AAAA、无序多跳链、无关 Answer/SOA、SOA+NS、AA 别名转介、无 SOA type 3 及旧格式未知。每类联合检查 parse_response、diagnose 和必要的 compare，不能仅靠字段存在判断通过。
